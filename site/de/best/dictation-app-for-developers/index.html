Die eigentliche Aufgabe

Du beschreibst einem Coding-Agenten einen Fehler, statt eine Funktion Zeichen für Zeichen zu diktieren. Die kritischen Stellen sind Dateinamen, Verneinungen, Versionsnummern und die Trennung zwischen Beschreibung und ausführbarem Code. Ein flüssiger Absatz hilft wenig, wenn aus „nicht überschreiben“ ein anderer Auftrag wird.

Worauf es ankommt

  • Verneinungen und Einschränkungen unverändert erhalten.
  • Eigene Projektnamen und Fachbegriffe kontrolliert ins Wörterbuch übernehmen.
  • Im tatsächlichen Editor testen, nicht nur in einer Demo.
  • Prompts und Quellcode als getrennte Eingaben behandeln.

Ein passender Ablauf

Sprich zuerst Ziel, Einschränkungen und Abnahmekriterium. Ergänze Pfade, Befehle und Variablennamen anschließend mit der Tastatur. Für einen Agenten ist ein präziser Auftrag nützlicher als ein langer, automatisch umformulierter Monolog.

Dein praktischer Vergleich

Diktiere ein Bug-Ticket mit „nicht löschen“, einem gemischten deutschen und englischen Fachbegriff und einer Versionsnummer. Prüfe danach denselben Text im Editor und im Browser. Miss auch Korrekturzeit und Einfügefehler, nicht nur die Dauer bis zum ersten Text.

Wann du anders wählen solltest

Wenn exakte Codezeichen oder ein Firmenstandard zwingend sind, nimm keine App allein aufgrund ihrer Diktierdemo. AInauten Voice garantiert kein korrektes Einfügen in jedes Editorfeld; kompatibles Einfügen über die Zwischenablage ist eine bewusste Option.

Eine häufige Frage

Kann ich damit Code diktieren?

Beschreibungen und Prompts sind ein sinnvoller Einstieg. Für ausführbaren Code musst du Zeichen, Einrückung und Syntax separat prüfen; wir haben keine Genauigkeitsrangliste für Code gemessen.
